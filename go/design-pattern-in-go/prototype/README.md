## 概要

Prototypeは生成に関するデザインパターンの一つで、**クライアント**が既存のオブジェクトをそのクラスに依存することなく複製（クローン）できるようにするパターン。

> prototypeとは: 原型、試作品
>
> (https://ejje.weblio.jp/content/prototype)

オブジェクトの生成コストが高い場合や、複雑な初期化を避けたい場合に、既存のインスタンスをコピーして新しいインスタンスを作成する。

## どんな問題を解決するのか

### 問題の具体例

ファイルシステムのコピー機能を考える。

- ファイルとフォルダが階層構造を持っている
- フォルダは複数のファイルや他のフォルダを含むことができる
- 構造全体をコピーしたい場合:
  1. （呼び出し側が）各オブジェクトの具体的な型を知る必要がある
  2. ファイルとフォルダでコピー処理が異なる
  3. 階層が深くなると、再帰的なコピー処理が複雑になる
  4. 新しい種類のノード（シンボリックリンクなど）を追加するたびに、コピー処理を修正する必要がある

理想: オブジェクトの具体的な型を知らなくても、統一的な方法でコピーしたい

## どう問題を解決するのか

### 解決策

Prototypeパターンでは以下のアプローチを取る:

1. 複製機能（clone）をオブジェクト自身に委譲する
2. 共通のインターフェースを定義し、すべての複製可能なオブジェクトがそれを実装する
3. クライアントは具体的な型を知らずに、インターフェース経由で複製を要求できる

### 構造

```
┌────────────────────┐
│   <<interface>>    │
│       Inode        │
├────────────────────┤
│ + print(indent)    │
│ + clone() Inode    │
└────────────────────┘
          △
          │
 ┌────────┴────────┐
 │                 │
┌┴───────────┐  ┌──┴──────────┐
│   File     │  │   Folder    │
├────────────┤  ├─────────────┤
│ - name     │  │ - name      │
├────────────┤  │ - children  │
│ + print()  │  ├─────────────┤
│ + clone()  │  │ + print()   │
└────────────┘  │ + clone()   │
                └─────────────┘
                      │
                      │ contains
                      ▼
                   Inode[]
```

## 使いどころ

### 適用すべき場面

| 場面 | 説明 |
|------|------|
| オブジェクトの生成コストが高い | データベースからの読み込みや複雑な計算が必要な場合、既存オブジェクトをコピーする方が効率的 |
| 具体的なクラスに依存したくない | クライアントがオブジェクトの具体的な型を知らずにコピーしたい場合 |
| 階層構造のコピー | ツリー構造やグラフ構造など、複雑な構造を持つオブジェクトを再帰的にコピーする場合 |

### 具体的な適用例

- ファイルシステムのコピー: ファイルとフォルダの階層構造を複製
- ゲームのオブジェクト複製: 敵キャラクターやアイテムのテンプレートから新しいインスタンスを生成
- 設定オブジェクトのコピー: デフォルト設定をコピーしてカスタマイズ
- GUIコンポーネントの複製: テンプレートとなるウィジェットをコピーして配置

## 長所と短所

### 長所

- 具象クラスへの依存を減らせる: クライアントは具体的なクラスを知らずに複製できる
- オブジェクト生成の効率化: 複雑な初期化プロセスを省略できる
- 複雑なオブジェクトの簡単な複製: 階層構造やグラフ構造を持つオブジェクトも統一的に複製
- 継承に代わる手段: サブクラスを作る代わりに、プロトタイプを使った設定が可能
- (追記)OCPを満たしている

### 短所

- 循環参照の扱い: 循環参照を持つオブジェクトの複製は複雑になる
- 深いコピー vs 浅いコピー: どの程度までコピーするかの判断が必要

(とはいえこれはprototype patternを利用しなくてもつきまとう課題なように思える)
